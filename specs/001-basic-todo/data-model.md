## Entities & Schemas

### 1. Todo Item (`Todo`)

Represents a single task entry created by a user.

| Field Name | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `Long` | Primary Key, Auto-increment | Unique identifier for the todo task. |
| `title` | `String` | Not Null, Size: 1–255 chars, Not Blank | The content or summary of the task. |
| `completed` | `Boolean` | Not Null, Default: `false` | Status indicating if the task is finished. |
| `createdAt` | `LocalDateTime` | Not Null, Auto-set on create | Timestamp when the task was first created. |
| `updatedAt` | `LocalDateTime` | Not Null, Auto-updated | Timestamp when the task was last modified. |

#### Database Mapping (JPA / H2 Table `todos`)
```sql
CREATE TABLE todos (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title VARCHAR(255) NOT NULL,
    completed BOOLEAN NOT NULL DEFAULT FALSE,
    created_at TIMESTAMP NOT NULL,
    updated_at TIMESTAMP NOT NULL
);
```

## State Transitions & Lifecycle

```text
[ Non-Existent ]
       │
       │ POST /api/todos (title != "")
       ▼
   [ ACTIVE ] ◄──────────┐
       │                 │
       │ PATCH /toggle   │ PATCH /toggle
       ▼                 │
  [ COMPLETED ] ─────────┘
       │
       │ DELETE /api/todos/{id} OR DELETE /api/todos/completed
       ▼
  [ DELETED ]
```

### State Rules
1. **Creation**: A new Todo starts with `completed = false`, `createdAt = now()`, and `updatedAt = now()`.
2. **Editing**: Updating the title keeps `completed` intact and refreshes `updatedAt = now()`.
3. **Toggling**: Toggling flips `completed` between `true` and `false` and refreshes `updatedAt = now()`.
4. **Deletion**: Deletes the entity record from the database.

---

## Validation Rules

1. **Title Validation**:
   - MUST NOT be null or blank (`@NotBlank`).
   - MUST NOT exceed 255 characters (`@Size(min = 1, max = 255)`).
   - Whitespace strings (e.g. `"   "`) are rejected with `400 Bad Request`.
2. **Status Validation**:
   - `completed` must be a valid boolean value.
